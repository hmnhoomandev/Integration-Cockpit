# Phase 2 · Excel import and quality acceptance

In the synthetic HTTPS demo, sign in and choose **Data & reports**. Select September 2026 on **Re-import synthetic month**. Those workbooks are already seeded on the public demo, so the existing snapshot is reused. Then select October 2026 on **Run incomplete test import**. The app submits a generated set with the language workbook intentionally omitted. It reports the missing source and keeps September selected. Use **Download import quality report** immediately or after refreshing the page.

The workbook has three sheets. **Import** identifies the active snapshot separately from the attempted report date. **Sources** lists accepted row counts and SHA-256 checksums. **Issues** lists dataset, Excel row, localized diagnosis and stable reason code. Diagnostics are scoped to the session that ran the import. The workbook contains no names, case identifiers, raw values or uploaded filenames. Source row references from the results workbook can be matched to these checksums and the original input. Replaying an older snapshot fills in checksums when the same input files are available.

The public profile blocks arbitrary uploads. Local judge and importer accounts can upload 11 XLSX files, including the [generated monthly fixtures](https://github.com/hmnhoomandev/Integration-Cockpit/releases/download/v0.1.0-hackathon/synthetic-months.zip). Regression tests verify that rejected imports keep the exported results byte-for-byte unchanged. All supplied original template headers match the schema. Representative case-bearing municipal exports and approval for their use remain external acceptance dependencies.
